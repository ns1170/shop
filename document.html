デュアルモード型ECプラットフォーム
「WonderMarket」の設計と実装

開発プロジェクトチーム ／ 2026年10月
【概要】 本稿では，Web標準技術（HTML5/CSS3/モダンJavaScript）およびPython軽量RESTful APIバックエンドを統合したハイブリッド型ECプラットフォーム「WonderMarket」の設計と実装について報告する．本システムは，同一基盤上で「購入者向けカタログ・購買UI」と「販売者向け店舗・受注管理ダッシュボード」を完全分離かつ動的に同期させる二重モード構造を実現している．さらに，ローカルサーバー環境（ポート80）でのJSONファイル永続化と，GitHub Pages等の静的ホスティング環境でのLocalStorageフォールバック機構を自動判別するデュアル実行機構を導入し，高いポータビリティと実用性を両立した．

1. はじめに

現代のEコマース（EC）システムは，決済・在庫・注文処理などの多岐にわたる機能を持ち，その開発・運用環境の複雑化が課題となっている．特に初学者教育やプロトタイピング環境においては，過剰な依存関係（重厚なフレームワークや外部DB）を排しつつ，実運用に近い購買・販売サイクルを安全に検証できる軽量なシステムが求められる．

本研究では，Python標準ライブラリのみで動作するRESTfulサーバーと，依存ライブラリゼロのモダンフロントエンドを組み合わせ，即時ブラウザ起動，実金銭取引のない安全な疑似決済，およびGitHub Pages対応の静的公開を同時に満たす統合Webアプリケーションを開発した．

2. システムアーキテクチャ

本システムの根幹は「トリプルフォールバック型データ層」と「状態共有フロントエンド」である．

2.1 バックエンド: Python標準HTTP/API

外部ライブラリ（FlaskやFastAPI等）に依存せず，Python 3標準のhttp.serverモジュールを拡張して実装した．

  • ポート80直接待受: http://localhost で追加ポート番号不要のアクセスを実現．
  • RESTfulエンドポイント: 商品CRUD（/api/products），注文・在庫減算処理（/api/orders），ステータス変更（PATCH），デモ初期化（/api/reset）を提供．
  • JSON永続化: DB不要でdata/*.jsonに原子的に保存．

2.2 フロントエンド: Vanilla JS構成

ReactやVueを用いず，Web標準のDOM APIでSPAライクな画面遷移を構築した．画像切損を防ぐため，全商品アイコンはインラインSVGベクターとして動的描画される．

3. 主要機能の実装

3.1 購入者向けストアフロント (Buyer Mode)

一般消費者が直感的に閲覧・購買できるUIを提供する．

  1. 動的カタログ: リアルタイム検索，カテゴリ抽出，価格・評価ソートを即時実行．
  2. 商品詳細モーダル: 高精細SVGプレビュー，在庫アラート，スペック表示．
  3. スライドイン・カート: 数量変更，10%消費税・合計額の自動計算．
  4. デモチェックアウト: 配送先入力後，疑似決済をシミュレート．実取引は発生せず，注文番号を発行．

3.2 販売者向けダッシュボード (Seller Mode)

店舗運営者が受注と在庫を一括管理するコンソールである．

  1. KPIサマリー: 総売上高，注文件数，出品数，在庫僅少警告（5点以下）を表示．
  2. 出品・在庫管理: 新規出品，編集/削除，テーブル上での直接在庫増減（+ / -）．
  3. 受注追跡: 「受付→準備中→発送済→完了」のステータス更新．
  4. 売上アナリティクス: 週間売上バーチャート，カテゴリ比率を自動集計．

4. ハイブリッド同期機構

本システムのデータ層（store.js）は，起動時に自動環境判別を行う．

  • ローカル実行時: /api/products への通信に成功した場合，Pythonサーバーと同期し，他端末や再起動後もデータが保持される．
  • 静的ホスティング時: GitHub Pages等では自動的にブラウザ内localStorageへフォールバックする．

この設計により，同一コードベースのままGitHubリポジトリとして世界中にWeb公開可能となった．

5. おわりに

本稿では，軽量・高ポータブルなECアプリ「WonderMarket」の実装について報告した．ポート80での即時起動，購入者・販売者間の完全なデータ連動，GitHub Pages公開適合性を実証した．今後の課題として，ユーザー認証機構の追加が挙げられる．
